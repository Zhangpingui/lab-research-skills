# 科研材料的文献检索与证据入库

本流程用于为国自然、纵向项目、横向技术方案和研究报告补充可追溯文献。先明确检索任务，再选来源；“找到一篇相关论文”和“论文支持正文中的具体主张”是两件事。

## 先定义检索任务

将用户需求归入一种或多种任务，并分别记录：

- `landscape`：了解研究脉络、主流路线和代表工作；
- `claim_support`：为正文中的具体陈述寻找支持或反证；
- `nearest_work`：寻找与拟议方案最接近的工作，限定创新边界；
- `recent_update`：核查指定截止日期前的最新进展；
- `citation_verify`：核验题名、作者、年份、期刊、DOI 和引用内容是否一致。

每个任务形成查询矩阵：核心对象、任务、方法、场景/条件、同义词、排除词、年份范围和语言。雷达/SAR 主题同时考虑完整术语与缩写，例如 `synthetic aperture radar OR SAR`、`phased array OR array calibration`、`small target detection OR weak target detection`，再叠加海杂波、斑点噪声、复数域、检测协议等限定条件。不要只用用户最初的一条自然语言查询。

## 来源分层与回退

优先选择结构化、可核验的一手来源：

1. `T1`：Crossref、arXiv、出版方论文页、作者/项目官方页面；工程领域优先核对 IEEE、IET、SPIE、Elsevier 等出版方元数据和正文页面。
2. `T2`：Semantic Scholar 等带稳定元数据或引文图谱的聚合服务，用于扩展相近工作和被引/引用链。
3. `T3`：Google Scholar、CNKI、万方或普通网页检索。它们用于补漏时要记录访问边界；抓取不稳定、机构权限或手工检索不能伪装成系统性覆盖。

若宿主提供多源学术检索工具，可以并行查 T1 来源；否则使用可用网页/API 顺序检索。网络不可用时保留查询矩阵和待查清单，不能声称已经完成查新。

## 筛选、去重与排序

先按标题和摘要做初筛，再根据任务决定是否必须取得全文。去重顺序：

1. 标准化 DOI（去掉 `https://doi.org/`，转小写）；
2. 无 DOI 时比较标准化题名与第一作者；
3. 同一工作的预印本和出版版优先保留元数据更完整、状态更明确的出版版，并保留版本关系。

排序不使用单一“创新分数”。综述任务重视覆盖和代表性；查新重视时间、机制接近度与实验场景；正文引证重视语义支持强度。引用次数只能作为辅助信号，不能替代相关性和证据质量。

## 证据等级

每条来源都记录实际读取范围：

| 等级 | 可做什么 | 不可做什么 |
|---|---|---|
| `metadata_only` | 确认论文身份、年份、DOI | 判断论文是否支持技术结论 |
| `abstract_only` | 说明作者在摘要中声称什么 | 核实实验条件、数值和边界 |
| `full_text` | 支持有页码/章节定位的文本主张 | 自动视为图表已经核对 |
| `figure_table` | 支持已查看图表或公式的具体主张 | 外推到未报告场景 |

正文主张通过 `claim_id` 连接一个或多个 `source_id`，并记录 `supports / partial / contradicts / unresolved`、定位、适用条件和人工核实状态。题名相似或摘要命中不能直接写成“已有研究表明”。

## 推荐产物

- `search-plan.md`：问题拆解、查询矩阵、来源和时间边界；
- `references.json`：去重后的元数据、版本关系和读取等级；
- `claim-evidence.json`：正文主张、来源、定位和支持状态；
- `literature-map.md`：按技术路线、假设和失效条件组织的综合，不按论文逐篇罗列；
- 可选 `.bib` / `.ris`：仅包含已核验元数据。

交付时报告检索日期、数据库/网页、查询式、筛选范围和未覆盖来源。若用户要求“最新”或“全面”，必须说明截止日期和覆盖边界。
