# 多 Agent 论文精读与改进设计

本模式用于全文精读、证据审计以及“提出适合课题组验证的改进思路”。普通摘要和局部解释不启用，以免增加成本却只得到重复摘要。

## 主 Agent 先准备共享事实

解析论文一次，记录文件 SHA-256、论文版本、PDF 物理页、可提取文字页和已视觉查看页。建立课题组画像，分为 `confirmed_capabilities`、`available_resources`、`constraints` 和 `unknowns`。设计文档中的模块只能证明方案或接口存在；除非材料明确说明已实现并可调用，不能升级为现成代码、数据或设备。

## 第一波独立精读

同一轮最多派发三个角色，彼此不看输出：

1. `mechanism`：恢复问题、输入输出、信号或数据流、关键公式、模块作用、依赖假设与适用范围。
2. `evidence`：核对数据划分、指标口径、基线公平性、消融、数值一致性、负面结果、图表和作者结论之间的支持关系。
3. `domain`：检查雷达观测与杂波条件、SAR 数据类型和切片泄漏、小目标定义、相控阵误差，及结论能否外推到本组场景。

每个角色返回一个符合 [交接协议](agent-packets.md) 的 JSON 包。涉及图、表或复杂公式的结论必须实际查看对应页面，否则写 `unresolved`。

## 主 Agent 的证据闸门

将角色 finding 归并为稳定的 `C01`、`C02` 主张，并保留原 finding ID。发生冲突时检查来源、指标口径和实验条件，不以票数决定。

进入第二波前至少确认：

- 论文身份、版本和读取范围明确；
- 核心方法与主要实验主张有页码及图表/公式锚点；
- 指标同时保留比较对象、数据集和评价协议；
- 改变判断的视觉材料已核对，或明确保留未解决状态；
- 关键冲突已解释，或作为 `unresolved` 留在账本中。

闸门未通过时可以交付解读和待补证据，但改进思路只能标记为“先补证据”。

## 第二波改进与反证

第二波角色主要读取证据账本、课题组画像和必要原文片段：

1. `idea`：从失效条件、未区分解释、物理假设不匹配和适用边界提出候选。每项必须依赖至少一个 `Cxx`，不能把简单加模块、加数据或加参数当作知识增量。
2. `falsifier`：为候选寻找竞争解释、公平对照、最近邻工作风险，以及能推翻或收缩结论的结果。未执行在线查新时写“需查新”。
3. `feasibility`：按课题组画像设计最小验证，包括数据或仿真、基线、单一关键变量、指标、资源、停止条件和后续升级路径。

主 Agent 最终保留不超过 3–5 张改进卡，使用“可优先试验、先补证据、暂缓”三级建议，不使用创新分数或成功概率。

## 输出与停止条件

- `paper-notes.md`：核心意思、机制、关键证据、边界和未解决分歧。
- `claims.json`：稳定主张、定位、支持关系、读取范围和来源角色。
- `idea-cards.md`：依据、假设、最小验证、竞争解释、失败条件、资源缺口、查新状态和建议等级。
- `run-manifest.json`：论文哈希、skill 版本、画像哈希、完成角色、可读页和视觉核对页。

只在缺失证据可能改变核心判断时追加一次定向回查；角色失败只重试一次。检查点保存哈希和派生文件引用，不重复保存整篇论文正文。
