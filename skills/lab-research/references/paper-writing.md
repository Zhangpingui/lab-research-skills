# 学术论文主线设计与章节写作

本流程用于雷达、相控阵天线、SAR 图像和小目标检测论文的选题凝练、提纲设计、分节起草与结构重构。它复用已有论文解读、文献检索和实验事实，不用流畅措辞掩盖证据缺口。

## 先建立写作契约

从用户材料确认论文类型、目标读者或投稿方向、语言、篇幅/模板、希望处理的章节、真实实验结果和禁止披露内容。没有目标期刊时先处理科学内容，不硬编码标题词数、摘要长度、引言页数、时态、字体或参考文献数量。

将输入区分为：

- `confirmed_result`：作者确认且能回到数据、图表或记录的结果；
- `source_fact`：能回到文献具体位置的事实；
- `interpretation`：对结果或文献的解释；
- `hypothesis`：尚待检验的判断；
- `planned_work`：准备开展但尚未完成的工作；
- `unknown`：缺少信息、检索或实验。

可以从 `paper-notes.md`、`claims.json`、`idea-cards.md`、`references.json` 和 `claim-evidence.json` 读取已有事实；不要重新解析已经有可靠定位的材料。

## 一篇论文，一个中心命题

起草前先生成 `paper-story.md`：

```yaml
problem: "论文回答的一个具体问题"
importance: "为什么该问题值得解决"
gap: "最接近工作在什么条件下仍不能回答或处理什么"
core_idea: "本文一个可复述的核心思路"
main_claim: "希望证据支持的中心命题"
evidence: ["E01", "E02"]
boundary: "适用条件、代价和不能外推的范围"
audience: "目标读者或投稿方向"
```

中心命题不能只是“提出一个新模型”“完成若干实验”或“提高精度”。它应说明新方法、认识或能力相对什么基线，在什么条件下带来什么可解释增量。若论文确有多个相互独立的中心命题，先判断是否应拆成多篇，而不是把所有工作堆入一篇。

## 从主张和证据反向搭提纲

先建立章节—段落—主张—证据映射，再写连续正文。每个核心贡献至少回答：

1. 它与最接近工作的实质差异是什么；
2. 方法或分析在哪里兑现这一差异；
3. 哪个实验、推导或实测结果支撑它；
4. 哪个结果会削弱或推翻它；
5. 适用边界和代价是什么。

推荐写作顺序为：核心图表与结果 → 问题定义/方法/分析 → 实验与讨论 → 引言与结论 → 摘要与标题。用户只要求局部章节时不强制完成全流程，但应指出该章节依赖的未提供信息。

## 章节契约

| 部分 | 必须完成的任务 | 常见失误 |
|---|---|---|
| 标题 | 让读者识别研究对象、关键问题或方法特色 | “一种新的方法”过于空泛；为了关键词堆满细节 |
| 摘要 | 独立说明必要背景、具体瓶颈、核心思想、主要贡献、证据和边界 | 只写流程；无条件地声称显著、最优或首次；复制引言/结论 |
| 引言 | 完成重要性、现状分类、具体缺口、本文思路、贡献和必要的结构说明 | 写成学科历史；逐篇罗列；贬低前人；贡献在正文没有兑现 |
| 相关工作 | 按技术路线、假设、输入信息或失效条件分类比较，并定位本文 | 只换一种方式重复引言；把“近期”当作唯一选文标准 |
| 系统模型/问题定义 | 定义任务、输入输出、信号/系统模型、假设、变量、目标和约束 | 使用不必要的强假设；符号不一致；没有物理意义和单位 |
| 方法 | 按直观思想、方法概要、实现细节展开，说明为何有效 | 直接抛复杂公式；只有怎么做，没有为什么；琐碎推导淹没主线 |
| 理论/性能分析 | 给出成立条件、性能性质、复杂度或误差传播，并解释含义 | 定理后没有解释；把数学形式复杂当作贡献 |
| 实验/结果 | 说明为什么做、怎么做、观察到什么、支持哪条主张 | 让读者自己看图；不公平基线；只报最好结果；缺少复现条件 |
| 讨论 | 解释机制、与已有工作比较、说明局限、竞争解释和不能证明什么 | 复述结果；过度外推；回避负面结果和代价 |
| 结论 | 简洁回收方法、主要结果、贡献和由局限自然推出的后续问题 | 重抄摘要；重新讲背景；引入正文没有的新结果 |

具体实验和图表规则见 [实验与图表](paper-experiments.md)。

## 摘要和引言的最小结构

摘要通常包含五类信息，但不要求机械分成五句：

1. 必要背景或研究对象；
2. 具体问题或瓶颈；
3. 方法的核心思想；
4. 一到三个主要贡献；
5. 理论、仿真或实测证据；有可靠数字时写清指标、比较对象和条件。

引言先用最短篇幅把读者带到问题，再组织相关工作和缺口。贡献列表只保留最有分量的原创增量；做了仿真、搭了系统、换了数据集本身只是工作内容，除非它产生新的知识、方法、能力或适用边界。

## 相关工作的组织

先确定分类轴，再选择代表工作。每类工作回答：解决什么、使用什么关键假设或信息、优势是什么、在哪些条件下受限、与本文是什么关系。经典来源用于概念和方法源头，近期来源用于当前进展和最接近工作；引用必须实际支持对应句，元数据命中不能充当语义证据。

评价已有工作时保持克制。可以说明条件、代价或尚未验证范围，不使用无证据的“完全无法”“显著落后”。如果需要查新或补引用，转入 [文献检索](literature-search.md)。

## 方法的三层表达

1. **基本思想**：用简明语言、例子或示意图说明设计动机；
2. **方法概要**：给出主流程和模块关系，让读者不读全部推导也能理解；
3. **方法细节**：给公式、伪代码、复杂度、实现条件和例外情况。

定理、算法或关键公式后解释其物理、统计或工程含义。长证明和非主线推导可放附录，但正文必须保留理解贡献所需的条件和结论。

## 段落和语言

每段只承担一个主要任务：主题句提出主张，后续句通过原因、证据、比较、限制或结果展开，结尾给出结论或过渡。连接词用于显式呈现真实的并列、递进、因果、转折、让步、列举、举例或总结关系，不能靠堆连接词伪造逻辑。

优先使用短而明确的句子和可测量表达。用具体指标替代“效果很好”，给“首次、最优、显著”限定检索范围、统计依据和适用条件。主动或被动语态以主语和责任关系清楚为准；不设置“不能用 we”“不能用 but”“全文只用一种时态”等绝对规则。

缩写、术语、符号、索引和单位保持一致。公式作为句子的一部分使用合适标点，并在首次出现时定义变量。目标期刊的大小写、拼写、标题风格和格式要求优先于通用经验。

## 推荐产物与停止条件

- `paper-story.md`：中心命题与边界；
- `claim-evidence.json`：主张、来源、结果和支持状态；
- `manuscript-outline.md`：章节—段落—主张—证据反向提纲；
- `manuscript-draft.md`：用户请求范围内的连续正文；
- `missing-evidence.md`：只保留会改变结论或定稿的缺口。

没有真实结果时可以交付故事线、提纲和实验计划，但停止在“待检验”状态。未查新时不得把贡献写成领域首次；关键数字无来源时不得用近似值补齐。整篇草稿完成后按 [模拟审稿](manuscript-review.md) 检查。
