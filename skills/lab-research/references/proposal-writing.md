# 申请书辅助起草与修改

按用户确认的“AI 辅助起草、人工修改定稿”协作。依据作者的真实研究设想、结果和文献工作，不代替作者决定科学主张或核实前期成果。

## 选择申请场景

| 场景 | 写作重点 | 首版支持范围 |
|---|---|---|
| 国自然 | 科学问题、知识增量、证据与可行性 | 主要场景，覆盖章节草稿、修改和预审 |
| 其他纵向 | 指南任务、研究内容、考核指标、组织实施 | 通用结构；具体以用户提供的指南为准 |
| 企业横向 | 对方需求、任务边界、交付物、测试与验收条件 | 通用技术方案；合同与预算条款需具体材料 |

优先确认申报年份、项目类别、当年模板、已有设想/草稿、真实前期工作和用户请求的章节。缺少模板时先提供内容结构，不虚构官方要求；期限、篇幅、申请代码与预算规则均从适用材料读取，不硬编码三年或固定经费。

年度规则参考：2026 年[基金委申请通告](https://www.nsfc.gov.cn/p1/3381/2824/99667.html)对 AI 使用、人工核实和说明提出要求，且限制 AI 直接生成申请书的使用；[申请书改版说明](https://www.nsfc.gov.cn/p1/3381/2821/99242.html)说明了面上和青年 C 类的调整。按申报年份核验并简要记录，不能把“人工修改过”自动认定为符合所有申报要求，也不反复打断普通梳理工作。

## 起草流程

1. 从真实材料形成简明事实表：已知结果、支持文献、拟研究内容、尚缺证据。尚未完成的实验不能写成已完成。
2. 明确论证关系：已有认识 → 具体未知 → 科学问题/可检验假设 → 研究内容 → 验证 → 预期知识增量。允许理论、方法和应用基础研究采用不同表达，不强制套用“机制”叙事。
3. 按用户所需章节给出提纲或草稿。研究设想过少时，提供问题凝练、写作骨架和待补项，不凭空生成团队成果或全套细节。
4. 用连贯段落表达。内部检查表与编号不必进入申请书正文；在草稿旁提供简短“依据/待核实”说明，方便作者修改。
5. 检查跨章节一致性，交付新版本与重要修改理由。

## 各部分应解决的问题

| 内容 | 起草和检查重点 |
|---|---|
| 题目与摘要 | 对象与问题清楚；概括方法和预期贡献；字数取自实际模板 |
| 立项依据 | 从可核验现状定位具体未知；说明为什么值得研究；避免把工程需求直接充当科学问题 |
| 研究内容 | 每项说明目标、做法、比较对象和验证；保持研究逻辑的依赖关系 |
| 特色与创新 | 对照最接近工作写清实质差异与预期知识增量；未查新不能写“首次” |
| 研究基础 | 仅采用作者确认的论文、数据、仿真、实测和设备；解释与拟研究工作的关系 |
| 年度计划 | 由研究内容和真实项目期限推导；里程碑体现验证结果和依赖关系 |
| 预算说明 | 仅在项目类型要求且用户提供依据时组织；缺报价/规则就标待补，不编金额 |

研究假设是可被结果挑战的陈述；科学问题是待回答的问题；提高检测精度、做出系统属于目标或成果，需进一步解释背后的认知问题。

## 修改与预审

每条问题包含“位置—问题—依据—影响—建议”，区分事实错误、论证不足和表达建议。优先检查：

- 文献是否真实，且内容支持引用句；元数据相符不足以证实语义支持。
- 科学问题是否具体，创新点是否有对照，研究内容是否真的回答问题。
- 仿真、公开数据实验、实测结果及未来计划是否混用。
- 目标、指标、条件、期限、术语和研究基础是否前后矛盾。
- 实验能否区分提出的解释与竞争解释；是否缺少会改变结论的关键对照。

报告按影响排序，给出优先修改的少量事项，不固定要求十条，不模拟正式评审结论或资助概率。

推荐交付 `proposal-outline.md`、所请求章节的 `proposal-draft.md` 或 `proposal-review.md`，以及确有缺项时的 `missing-evidence.md`。Word/LaTeX 导出使用用户模板和宿主可用工具；首版不自带排版引擎。
