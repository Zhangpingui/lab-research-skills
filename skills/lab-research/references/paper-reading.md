# 论文解读

## 先建立论文主线

确认题目、版本、研究任务和读取范围。先通过摘要、引言、结论和关键图表形成暂定理解，再回查方法、实验、附录。用户指定某一页或某张图时聚焦该部分，不默认扩成全文报告。

正文先用几句话回答：作者研究什么、旧方法哪里受限、做了什么改变、结果支持到什么程度。接着解释让读者真正理解方法所必需的部分。

## 方法解释

从输入到输出梳理信号、数据或信息的变化。说明每个关键模块解决的具体困难，为什么放在该处，以及它依赖什么假设。

- 公式：先讲物理或统计含义，再定义变量、单位、维度、成立条件。区分论文给出的推导和辅助推导。
- 图表：解释横纵轴、单位、实验条件、图例、对照、主趋势和不能推出的结论。
- 图像例子：注意动态范围、归一化、色标、裁剪和选择性展示，不能仅凭视觉更清晰就推断指标更好。
- 源代码：如果有且用户需要复现，可静态核对实现；代码、图表和文字冲突时并列报告，不自动以其中一个取代另一个。
- 教学类比：明确标为类比；不要用类比补齐缺失的物理机制。

## 根据论文类型评估

| 类型 | 优先检查 | 评价边界 |
|---|---|---|
| 理论或推导 | 前提、证明步骤、适用域、反例 | 不因没有实测就判定理论无效 |
| 算法或检测方法 | 数据划分、基线公平性、指标、消融、泛化、计算成本 | 单一数据集提升不能直接证明普遍有效 |
| 天线、阵列或系统 | 模型、边界条件、校准、仿真与测量、误差 | 只在作者声称的范围内判断；不强求所有层级验证 |
| 数据集或基准 | 标注、采样、重复数据、评价协议、代表性 | 区分数据可获得和真正可复现实验 |
| 综述 | 覆盖范围、组织方式、遗漏与论据 | 综述的结论仍需核对其所依赖的原始证据 |

将批评分为：已定位的错误、影响结论的证据缺口、值得尝试的改进。不要把“论文没有说明”改写成“作者没有做”。

## 对话问答与正式产物

只解释一个公式、段落、图表或事实且用户没有要求文件时，直接在对话中回答，不为局部问答机械创建文档。用户要求解读、精读、系统梳理整篇论文或形成可保存报告时，进入正式产物模式。

正式内容按需组织为：核心意思、方法解释、关键图表/公式、证据与边界、与本组研究的联系、问题与来源。简读可以较短；精读才展开全部内容。

数字记录指标名、比较对象和实验条件。重点核对：相对提升与百分点、文字与表格是否一致、训练/推理口径、参数量和硬件条件。

正式模式必须先用 `paper-notes.md` 保存完整正文，再从该文件生成 `paper-notes.docx`。不得分别起草两份内容，也不得让 Word 反向成为事实源；修改正文后重新生成 Word。只有用户明确要求单一格式时才可省略另一份。

关键主张的证据条目放在 `paper-notes.md` 文末，或在较大任务中单独保存为 `evidence.jsonl`。全文翻译不是本模式默认输出。

## 保留核心数据表和图片

选择能够直接解释研究问题、方法机制、主要结果或结论边界的最小充分图表集，不默认复制全部图片。正式产物采用以下目录：

```text
outputs/lab-research/<任务名>/
├── paper-notes.md
├── paper-notes.docx
├── paper-notes.qa.json
└── paper-notes-assets/
    ├── fig-<编号>-page-<物理页码>.png
    └── table-<编号>-page-<物理页码>.png
```

图片按以下规则保留：

- 先查看完整 PDF 页面，再从高分辨率页面渲染图中裁剪；保留必要的坐标轴、单位、图例、色标、子图编号和图题。裁剪后再次查看图片，确认没有截断或误配。
- 优先保存原始科学图表的忠实裁剪，不用生成式重绘、风格迁移或自动补全改变其内容。若只保留多子图中的一个面板，必须在说明中写明原图编号和面板编号。
- 图片嵌入 `paper-notes.md` 时使用相对路径，并紧邻相关解释。图片下写明“来源：原文图 X，PDF 物理页码 N”；图上估读的数值仍标为近似。

宿主没有直接裁剪能力时，可在查看完整页面并确定裁剪框后，使用脚本从页面渲染中生成可复现的 PNG。坐标采用左上角为原点的归一化 `x0,y0,x1,y1`：

```bash
python scripts/extract_pdf_region.py paper.pdf \
  --page 4 \
  --box 0.08,0.28,0.92,0.62 \
  --output outputs/lab-research/<任务名>/paper-notes-assets/fig-4-page-4.png
```

脚本会输出源文件指纹、物理页码、裁剪框、DPI 和图片尺寸。裁剪坐标只是复现记录，不能替代对原始完整页面和最终裁剪图的人工核对。

完成 Markdown 后，用同目录中的相对图片生成 Word：

```bash
python scripts/build_paper_notes_docx.py \
  outputs/lab-research/<任务名>/paper-notes.md \
  outputs/lab-research/<任务名>/paper-notes.docx \
  --report outputs/lab-research/<任务名>/paper-notes.qa.json
```

转换器支持标题、正文、列表、Markdown 表格、代码块和本地图片。图片路径必须相对 `paper-notes.md`，且不能逃出任务目录；引用图片缺失时停止生成，避免 Word 悄悄遗漏关键证据。生成 DOCX 后按 [Word 交付](word-delivery.md) 渲染全部页面并核对图片、图注和分页。

数据表按以下规则处理：

- 表格结构清楚且能逐格核对时，优先转写为 Markdown 表格，保留指标名、单位、比较对象、实验条件、脚注和缺失值含义。完成后逐格回查原表。
- 表格过宽、合并单元格复杂、符号密集或文字提取不可靠时，保留原表截图，不猜测或补齐单元格。核心数值可在正文另行列出，但须与截图一致。
- 对承担关键定量证据的表格，可以同时保留 Markdown 转写和原表截图：前者便于检索，后者用于视觉核对。

图表是否适合保留以论证价值为准。装饰图、重复示意图和无法解释的低清图片不必复制；无法可靠裁剪或核对时，在笔记中说明缺口，不以模糊截图冒充已验证证据。
