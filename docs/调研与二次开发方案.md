# 课题组科研 Skill：调研与二次开发方案

版本：v0.2 · 调研日期：2026-09-13 · 更新日期：2026-09-16 · 状态：多 Agent 开发版，供 review。

## v0.2 更新摘要

在 v0.1 单 Agent 路由之上，新增两阶段多 Agent 精读：第一波由机制读者、证据审计者和领域读者独立取证，主 Agent 形成主张账本并执行证据闸门；第二波由思路生成者、反证者和可行性设计者形成不超过 3–5 张改进卡。交接使用 JSON 协议和确定性结构校验，冲突回查原文而非多数投票。

架构思想参考 [PaperReading 固定快照](https://github.com/tuo3288/PaperReading/tree/030c74b2d7b4ef897787fb65ef322464d73e8f7a)，但未复制其代码或提示词。该仓库在核查快照中没有 LICENSE 文件，GitHub API 未识别许可证，README 的“HIT License”没有提供可执行条款，因此只借鉴角色拆分、问题预算和检查点概念。其工作流还存在配置中的追问阈值未接入状态图、问答历史按相邻消息配对可能错位、Reviewer 反复接收全文、PDF 解析只提取文本等问题，均未照搬。

首轮真实材料试运行使用 DenoDet 论文与一份跟踪/识别概要设计。论文提供了频域动态软阈值、DeGroFC、多数据集比较和消融；设计说明提供了轨迹特征、微多普勒、高频成像、三级识别及雷达/图像融合跟踪链路。试运行用于验证角色互补、来源定位、资源边界和最小实验设计，不把设计文档中的计划模块直接视为已可调用资源，也不宣称复现论文结果。

## 1. 建议与首版结果

建议采用一个 `lab-research` 入口，按任务加载论文解读、研究思路、申请书协作和领域要点。主要改编来源为 ChineseResearchLaTeX、K-Dense Scientific Agent Skills、BESSER-PEARL；选择了许可明确的相关部分，重新组织成轻量的中文课题组工作流。

你的需求与本版实现对应如下：

| 需求 | 首版实现 | 当前边界 |
|---|---|---|
| 国自然申请书辅助编写 | 科学问题凝练、提纲、分章节草稿、修改建议、跨章节检查 | 依据作者材料，人工修改定稿；未适配某一份实际申报模板 |
| PDF 核心意思与解释 | 本地逐页文字提取、核心方法解释、图表/公式核查流程 | 读取脚本不做 OCR；图表由宿主查看，不能只凭提取文字判断 |
| 改进思路与辅助梳理 | 证据来源、候选假设、竞争解释、最小验证、失败条件 | 新颖性需另行检索，尚未用真实课题组材料验证效果 |
| 雷达、相控阵、SAR、小目标检测 | 四类可选择的领域检查项 | 属于首版工作规则，后续用本组论文校准 |
| 横向、其他纵向 | 通用场景入口与写作重点 | 项目指南、企业任务书和专项模板后续补充 |

使用入口见 [README](../README.md)，实际技能见 [SKILL.md](../skills/lab-research/SKILL.md)。当前未安装到全局目录，也未执行任何远程发布。

## 2. 调研范围与证据强度

检索了 GitHub 上的研究申请书、NSFC、论文评审、PDF 解读以及雷达/天线相关 skills。主要查询包括 `SKILL.md research-grants`、`SKILL.md 国家自然科学基金 申请书`、`nsfc skills`、`radar SAR SKILL.md`、`相控阵 SKILL.md`、`横向项目 skill`。

本次对下表 8 个技能仓库和 1 个解析工具仓库取得了 GitHub API 元数据与默认分支 commit；对候选 `SKILL.md`、许可证及少量关键脚本进行了静态阅读。末节保存固定 commit，便于重复核查。未对全部上游安装、跑通或做模型效果横评；star 只作发现线索，不作为质量评分。

检索结果不足以证明市场上不存在其他工具。在本次范围内，没有核实到一个可直接覆盖“本组四个方向 + 国自然 + PDF 解读 + 研究改进”的完整技能，因此领域适配是本项目需要补充的部分。

## 5. 首版结构与工作方式

```text
skills/lab-research/
├── SKILL.md                       按用户任务选择模式
├── agents/openai.yaml             展示名称与默认提示
├── references/
│   ├── paper-reading.md           PDF 核心解释与证据判断
│   ├── research-ideas.md          改进思路与最小验证
│   ├── proposal-writing.md        申请书起草、修改、预审
│   └── domain-radar.md            本组四个方向的检查项
├── scripts/
│   ├── read_pdf.py                页码、指纹、文本、候选表格
│   └── requirements.txt
├── LICENSE
└── THIRD_PARTY_NOTICES.md          改编来源与原版权声明
```

论文路径：PDF/链接 → 获取可读内容与范围 → 解释方法与证据 → 可选的改进思路。

申请书路径：作者设想/草稿/前期成果 + 文献 + 当年模板 → 论证梳理 → 请求章节的辅助草稿/修改建议 → 作者核实与定稿。

两条路径共享关键主张的证据条目。这样读论文所得可以进入立项依据和选题讨论，同时保留出处与适用条件。首版使用 Markdown 和少量结构化记录，无需数据库、向量检索服务或多智能体运行框架。

按 skill-creator 的设计原则，将核心路由放在入口，专业细节按需加载，只有 PDF 读取采用确定性脚本，避免把整个上游技能库作为必要依赖。

## 6. 本领域必须补上的判断

| 方向 | 本版重点 | 希望避免的问题 |
|---|---|---|
| 雷达 | 输入信号、杂波假设、检测/虚警定义、观测条件 | 用缺少虚警条件的单个检测率直接比较方法 |
| 相控阵天线 | 互耦、幅相误差、频带/扫描范围、仿真与测量层级 | 把理想阵因子结果当作已验证整机性能 |
| SAR | 数据类型、分辨率、预处理、显示范围、来源场景划分 | 把视觉更清晰直接等同于检测更好；忽略切片泄漏 |
| 小目标检测 | 任务定义、目标尺寸口径、评价协议、公平比较、计算成本 | 混比像素级和对象级指标；混淆像素小与物理弱目标 |

这些是拟用于真实材料评测的领域规则，不是已经验证能提高中标率或科研产出的结论。正式选题需要进一步检索相关领域原始研究，并由组内研究者复核。

## 7. 首版验收与后续计划

### 当前可验证内容

PDF 脚本的自动化检查包括：选择非连续页时保留物理页码、低文字量页明确提示、相同文件指纹稳定、可选表格输出、非法页码/无效 PDF/加密 PDF 不能假装成功。技能还需验证 frontmatter、引用文件存在及基本可发现结构。

这些检查验证提取器和技能包结构，不能证明模型的领域解释或草稿质量。实际检查结果在本轮交付时记录。

### 真实材料验收样例（尚未执行）

| 样例 | 应观察到的行为 |
|---|---|
| 1 篇普通双栏 SAR 检测论文 | 核心结论能定位原文；方法解释不只复述摘要；重要数字带协议 |
| 1 篇含复杂公式的阵列论文 | 说明符号与假设；关键公式对照页面；不确定处明确标记 |
| 1 篇扫描或低质量 PDF | 不假装提取完整；指出具体不可读页及补救方式 |
| 只有摘要的论文 | 不补写全文实验或隐藏局限 |
| 不同划分/指标的两篇检测论文 | 先指出不可直接比较条件，再做有边界的分析 |
| 一份已有国自然章节草稿 | 不增加虚构成果；修改建议有位置、理由和证据缺口 |
| 没有前期成果的初步想法 | 形成研究问题与验证计划，不生成已完成实验 |
| 作者只要求 review | 只出报告，不改原稿 |

首次人工评测建议使用 2 篇本组熟悉的公开论文和一段可用于当前 AI 环境的申请书草稿，由熟悉材料的人检查：事实正确、关键论点可追溯、解释有帮助、建议值得验证。严重事实错误或虚构结果应逐项修正，不能用平均分掩盖。

### 开发顺序

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| v0.1 当前 | 一个入口、四份参考、文字读取器、归因与调研文档 | 基础结构与脚本验证；可通过文件路径调用 |
| v0.2 优先 | 用真实论文迭代领域规则，评估 Docling/其他解析后端，补图表定位 | 上述代表样例能复核；定位与阅读范围准确 |
| v0.3 按实际需求 | 国自然具体年度/类别模板；Word 或 LaTeX 导出 | 用课题组真实模板完成一次草稿修改与输出检查 |
| 后续扩展 | 横向任务书、其他纵向指南、组内资料复用 | 每新增场景有真实材料和验收案例，不靠通用模板声称全面支持 |

主要成本来自宿主模型与长文/图表读取；本版脚本不调用外部 API。复杂 OCR 可能增加本地模型下载、运行时间或外部服务费用，选定后再列出。尚未测量实际单篇耗时和费用。

## 8. Review 时优先看这几项

1. 一个入口、国自然与论文解读优先的范围是否合适。
2. 分章节辅助草稿和修改建议是否符合你们的人工定稿习惯。
3. 领域检查项有没有本组特别看重或不适用的内容。
4. 下一版优先接入哪一份国自然模板，以及用哪两篇论文做验收。

这几项用于后续迭代，不影响当前开发版读取材料和输出辅助结果。
